### 真机运行

环境：Android 14、微信 8.0.78、模型 `k3[1m]`，线上示例版本未知。

两轮均保留原操作与预期，每轮 15 个直接证据引用属于各自 Suite。中间状态和最终状态与回填一致，但执行中有异常：

- 第一轮：缺少当前视觉帧时拒绝执行；开关切换后，画面变化未达阈值而超时。随后根据画面继续。
- 第二轮（视频对应运行）：已进入 input 页面，但无障碍文本后置条件超时，随后根据画面完成输入。

第二轮保留了连续原片，第一轮没有。原始日志、截图和异常记录留在私有验收资料中。

## 真机验收清单

先按 [示例指南](../examples/README.md#当前状态与预检) 核对页面。仅使用授权设备和本地示例组件，不绕过账号或权限限制。

| 场景 | 通过条件 |
| --- | --- |
| 正常完成 | 五例的中间状态、最终状态与回填一致，证据属于本次 Suite，源用例不变。 |
| 失败取证 | 私有副本只运行输入例：操作仍为“示例甲”替换成“示例乙”，预期故意设为“示例丙”。应报告失败并保留“示例乙”截图，不修改操作或预期。其他阻塞不算通过。 |
| Stop/Continue | 分别在步骤间、动作进行中停止；停止后无新动作、写入或游标推进。继续时先观察，再恢复原 Suite，不重复已完成操作。 |
| 人工输入 | 等待用户给出测试短语；收到前不填默认值、不操作、不推进，收到后输入并核实。 |
| 设备断连 | 断连后不假报成功、不推进结果。连接恢复且用户选择继续后，先检查页面再恢复原 Suite。 |
| 新测试隔离 | 停止后另开测试，旧测试只读，新身份、进度和证据独立；完成后再开一次，同样无串用。 |

每次保留用例哈希、时间、系统/微信/示例版本、模型名、Run/Suite/attempt 标识、结果文件、截图、日志和连续录像。未知版本注明未知；失败尝试也须保留。

发现缺陷时暂停放行，保留复现证据；不删失败用例、不放宽断言、不加示例专用执行分支。
